# ドキュメントの書き方

対象は `CLAUDE.md`・`README.md`・`docs/`・業務フォルダの `README.md` と `docs/`・コードのコメント。

## 今のことだけを書く

- 今どう動くか・今のルールと、その理由だけを書く
- いつ何を変えたか・前はどうだったかは書かない。git に残っている。書くと、今の説明が経緯に埋もれ、古い記述が直されないまま残る
- 「〜はしない」という理由は、過去の出来事としてではなく、そうすると何が起きるかとして書く

## 同じことは 1 か所に書く

- ルールは `docs/` のどれか 1 か所に書き、ほかからはリンクする。何か所にも書くと、直すときに直し漏れが出て食い違う
- `README.md` には、リポジトリの紹介と始め方だけを書き、ルールは `docs/` にリンクする

## 業務フォルダの README

`_template/README.md` の見出しに沿って、次を書く。

- 何をするか（1〜2 文）
- 流れ（usecase の順。どの工程で何をファイルに残すか）
- 実行方法と引数
- 出力

## 業務フォルダの docs

各ファイルに書くことは [構成とファイルの役割.md](構成とファイルの役割.md#業務の資料docs) にある。

- `依頼文.md` は原文を手を加えずに貼る。要約や言い直しをすると、依頼元が何と言ったかを後から確かめられなくなる
- `依頼文.md` は、「今のことだけを書く」の例外として、届いた順に足していく。依頼が途中で変わった経緯も、依頼の中身の一部だから
- `依頼の背景.md` と `業務メモ.md` は、ほかのドキュメントと同じく今のことだけを書き、変わったら書き換える
